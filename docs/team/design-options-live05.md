# LIVE-05 사무실 메인 화면 — 디자인 선택지

작성: designer, 2026-11-25. 상태: **선택 대기**(사용자 결정). 이 문서는 DESIGN.md·design-spec-stage1.md를 바꾸지 않는다. 선택이 확정되면 그때 두 문서와 새 명세를 갱신한다.
근거 문서: `docs/team/reports/live-connection-2026-11-25.md`(LIVE-04·05), DESIGN.md(6절 임시 사무실·12절·2.1·9절), design-spec-stage1.md 3.8, 현재 화면 스크린샷(`screens/design/dashboard-1280-light.png`, `screens/qa/dashboard-390.png`).

## 1. 현재 구조와 문제

현재(1280): 위에서 아래로 승인 대기 띠 → 플랜 사용량 → 프로젝트 필터 → **3열(세션 목록 360 / 세션 상세 가운데 / 임시 사무실 360)**. 390: 같은 순서를 한 열로 쌓아 사무실이 맨 아래.

| 문제 | 내용 |
|---|---|
| 정보 중심이 상세 | 모델, 스킬 칩, 부른 BOT, 현재 도구는 세션 상세(AgentRow)에만 있다. 사무실 아바타는 이름+상태 문구뿐 |
| 사무실이 작고 선택 종속 | 360px 열(안쪽 약 334px, 4칸/줄)에 **선택한 세션의 BOT만** 그린다. 세션을 고르지 않으면 바닥이 없다 |
| 세션 간 비교 불가 | 다른 세션의 승인 대기는 목록 막대와 상단 띠로만 알 수 있고 사무실에서는 안 보인다 |
| 390에서 사무실이 맨 아래 | 상세까지 스크롤한 뒤에야 보인다 |
| 접근성은 지금 구조에서만 성립 | 사무실은 보조 표현이라 `aria-hidden`(플랜 미니) / 목록(BOT) + 상세가 같은 정보를 준다. 사무실이 메인이 되면 이 근거가 사라진다(4절) |
| LIVE-04 | 끝난 BOT이 30분·10분 남고, 같은 역할이 여러 번 호출되면 중복 아바타가 생긴다 |

요구(LIVE-05): 세션 상세를 따로 보지 않아도 사무실에서 **상태 · 승인 대기 · 현재 도구 · 스킬 · 모델 · 플랜 사용량**을 모두 파악.

## 2. 공통 전제 (세 선택지 모두)

사무실 안에서 정보를 보이는 도구는 DESIGN.md 12.6의 것을 확장해 쓴다. 새 UI 종류를 만들지 않는다.

| 정보 | 보이는 방법 (공통) | 항상 보임 / 눌러서 |
|---|---|---|
| 상태 | 아바타 사각형(상태 bg + 2px fg 테두리 + 아이콘) + **말풍선**(아이콘 + 문구, 12.6) | 항상 |
| 승인 대기 | 승인 대기 구역 배치 + 말풍선 "승인 대기 · N분째" + 방(세션) 머리 배지 + 기존 WaitingBanner(누르면 해당 방으로 이동·포커스) | 항상 |
| 현재 도구 | 말풍선 문구 "작업 중 · Bash"(기존 StatusBadge 문구 그대로) | 항상 |
| 모델 | 방 머리의 세션 모델(말줄임 + title). BOT별 모델이 다르면(LIVE-03 수정 후) **툴팁 카드**에 | 세션: 항상 / BOT: 눌러서 |
| 스킬 | 이름표 옆 "스킬 N" 작은 카운트(caption). 스킬 이름 칩 목록은 **툴팁 카드**(호버·탭·Enter) | 개수 항상 / 이름 눌러서 |
| 부른 BOT | 같은 역할 합침 카운트(×N, 아래 2.2)와 툴팁 카드 "qa ×3" | 눌러서 |
| 플랜 사용량 | 사무실 맨 위 **계기판 띠**(현재 PlanUsageMini를 키운 형태: 5h·7d 막대 + % + 수준 아이콘 + "마지막 측정 N분 전"). 12절 벽 계기판은 3단계 그림 | 항상 |
| 세션 정보 | 방 머리 이름표: 프로젝트(h3 말줄임), 브랜치(mono), 모델, 세션 상태 배지, 클라우드 배지 | 항상 |

툴팁 카드 = 12.6 이름표와 같은 형태(surface, 1px ink, caption/small ink). 열기: 마우스 호버, 터치 탭, 키보드 포커스 + Enter. 닫기: 바깥 탭, Esc. 카드 안 내용은 프롬프트·응답·도구 입력 없이 도구 이름·스킬 이름·모델·시간만(DESIGN.md 8절 Don't 유지).

### 2.1 끝난 BOT이 사라지는 연출 (공통 제안, 시간 값은 사용자 결정 Q-5)

서버가 `done` BOT을 얼마나 오래 보낼지 정한다(LIVE-04 수정 방향). 화면 쪽 제안:

| 상태 | 제안 |
|---|---|
| `done` | 쉬는 곳에 **60초** 머문 뒤 퇴장(1단계는 이동 애니메이션이 없으므로 다음 폴링에서 그냥 제거). 3단계 그림에서는 문으로 걸어 나가 사라짐(12.1 "종료 = 문으로 나가 사라짐") |
| `ended` | 즉시 제거(현재도 표시 안 함) |
| 호출하지 않은 내부 에이전트 | 서버가 BOT을 만들지 않음(LIVE-04). 화면 처리 없음 |
| 유예 중 표시 | 이름표 caption "완료 · 곧 퇴장"은 만들지 않는다(문구 과다). 쉬는 곳의 `done` 아바타 그대로 |
| 모션 | `prefers-reduced-motion: reduce`면 즉시 제거. 사라질 때 스크린 리더 알림 없음(`aria-live` 금지, 3초 폴링) |
| 대안 | 즉시(0초): 가장 단순하지만 "방금 끝났다"는 신호가 없다. 5분: 쉬는 곳이 붐빈다. **60초 권장**(폴링 3초 기준 20번 확인 기회) |

### 2.2 같은 역할 BOT 여러 개 합치는 표현 (공통 제안, Q-6)

- 같은 세션·같은 역할(`role`)의 BOT은 **한 아바타 + 우상단 "×N" 카운트 칩**(ink 바탕 흰 글자 caption)으로 합친다.
- 합친 아바타의 상태 = 가장 주의가 필요한 상태(승인 대기 > 응답 없음 > 작업 중 > 생각 중 > 완료). 툴팁 카드에 개별 상태 나열("작업 중 2 · 완료 1").
- 승인 대기가 하나라도 있으면 합친 아바타 전체가 승인 대기 구역에 서고, 나머지는 카드로만 확인. 승인 대기 BOT은 **절대 합치지 않는다**(각각 보임)를 대안으로 둘 수 있다.
- 대안: 합치지 않고 최근 N개만. 아바타가 늘어 좌석 초과 문제가 커지므로 비추천.

### 2.3 BOT이 많을 때 (좌석 초과) 공통 규칙

12절은 책상 8~12 좌석 / 쉬는 곳 5+ / 승인 대기 4. 제안: 구역별 한도를 넘으면 **마지막 칸을 "+N" 칩**으로 바꾼다(칩을 누르면 그 구역의 전체 목록 카드). 우선순위는 승인 대기 > 응답 없음 > 작업 중 > 생각 중 > 완료 순으로 좌석을 차지한다. 승인 대기는 구역 한도(4)를 넘어도 "+N"으로 가리지 않고 줄을 늘린다(놓치면 안 되는 정보).

## 3. 선택지

목업은 `docs/team/reports/screens/design/options/`(샘플 데이터, 사각형 아바타, 코드 아님). 말풍선이 96px 칸에서 줄바꿈된 것은 목업 한계이며 실제는 칸을 더 넓힌다.

### (가) 사무실 하나에 모든 세션 — 세션별 방

세션 하나 = 방 하나. 모든 활성 세션의 방을 한 사무실 영역에 함께 둔다. 세션 목록·세션 상세 열은 없앤다.

**1280**
```
+------------------------------------------------------------------+
| agent-observer                              3초마다 갱신  [로그아웃]|
| [!] 승인 대기 1개 세션 (demo)  → 누르면 demo 방으로 이동/포커스     |
| 플랜  5h [####......] 42%   7d [########..] 84% (!)한도 가까움  3분 전|
| 프로젝트 [전체 (2)]  [방 보기|목록 보기]                            |
| +--------------------- 사무실 ----------------------------------+ |
| | +== demo main opus-5-5 [!승인 대기 3분째] ==+ +- other feature/x| |
| | | 승인 대기: (!)책임자                        | | 책상: (…)책임자| |
| | | 책상: (▶)QA ×3  (…)설계                     | | 쉬는 곳: 없음 | |
| | | 쉬는 곳: (✓)기획                            | +---------------+ |
| | +---------------------------------------------+                   |
| +------------------------------------------------------------------+
```
2열 방 격자(방이 3개 이상이면 줄바꿈). 승인 대기 방이 항상 앞, 굵은 테두리(3px status-waiting-fg).

**390**: 방을 한 열로 세로 나열. 승인 대기 방 → 나머지 순. 방은 **접힘 기본**: 접힌 방 = 머리 한 줄(이름·모델·상태 배지·BOT 요약 "승인 대기 1 · 작업 중 1"), 승인 대기 방과 마지막으로 열었던 방만 펼침. 방이 5개 이상이면 접힌 줄만 보여 한 화면 안에서 세션 전체를 훑는다. 플랜 계기판은 맨 위 고정이 아니라 한 줄 요약(5h 42% · 7d 84%!)을 헤더 아래에 둔다.

- **세션 상세 대체**: 방 머리가 세션 정보를 갖고, BOT 툴팁 카드가 BOT 상세를 갖는다. 세션 "정리"·"숨기기"는 방 머리 오른쪽 `⋯` 버튼(secondary, 44px) 하나로 옮긴다. 별도 상세 패널 없음.
- **승인 대기 강조**: 방 테두리 3px + 방 머리 배지 + 정렬 맨 앞 + 상단 WaitingBanner(누르면 해당 방으로 스크롤 + 포커스).
- **빈 상태**: 세션 0개 → 사무실 바닥 대신 패널 문구 "연결된 세션이 없습니다. 수집 설정 방법은 …" + 설정 안내(Note). 세션은 있고 모든 BOT이 퇴장 → 방은 남고 방 안에 "BOT 없음"(세션 자체는 `AgentRow` 없이 방 머리만).
- 방 개수가 많을 때: 오래된 idle 세션은 "숨긴 세션"(기존 HiddenSessions)으로 접는다.
- **강점**: 세션 전체를 한눈에, 승인 대기를 놓치기 어렵다. **약점**: 방이 늘면 가로·세로 공간 압박, 세션별 방마다 3구역이 반복돼 비어 보이는 구역이 많다.

### (나) 선택한 세션만 사무실, 목록은 얇게

사무실이 화면 주 영역(폭 약 2/3~3/4). 왼쪽에 얇은 세션 목록(220~240px)을 둔다. 사무실에는 선택한 세션 한 개만 그린다(현재와 같은 데이터 범위, 크기·정보만 확장).

**1280**
```
| [!] 승인 대기 1개 세션                                              |
| +-세션 2-----+ +------------------- 사무실 (demo) --------------+ |
| |>demo [!]   | | 플랜 5h 42% | 7d 84% (!)  측정 3분 전          | |
| |  BOT 3     | | demo main opus-5-5 [!승인 대기 3분째]           | |
| | other [..] | | 승인 대기: (!)책임자  ← 말풍선 "승인 대기 · 3분째"  | |
| |  BOT 1     | | 책상:     (▶)QA ×3  (…)설계                    | |
| +------------+ | 쉬는 곳:  (✓)기획                              | |
|                +-------------------------------------------------+ |
```
**390**: 맨 위 "세션 칩 줄"(가로 스크롤 금지 → 2열 칩 격자: 프로젝트명 + 상태 아이콘·문구, 최소 44px) → 선택 세션 사무실. 사무실이 첫 화면(플랜 한 줄 요약 아래)에 온다. 칩을 누르면 그 세션 사무실로 교체.

- **세션 상세 대체**: 현재 구조의 상세 열을 지우고 방 머리 + 툴팁 카드로 대체(가와 동일). 목록 행은 세션 이름·상태 배지·BOT 수·정리 버튼만(현재 SessionRow 축소판).
- **승인 대기 강조**: 선택하지 않은 세션의 승인 대기는 사무실에서 안 보이므로 **목록 행 막대 + 상단 띠**가 맡는다(현재와 같은 약점). 사무실 머리에 "다른 세션 1개 승인 대기" 링크(누르면 그 세션으로 전환)를 더한다.
- **빈 상태**: 세션을 고르지 않았을 때는 첫 승인 대기 세션, 없으면 가장 최근 활동 세션을 **자동 선택**(현재의 "세션을 고르면 BOT이 보입니다" 빈 화면을 없앰). 세션 0개는 (가)와 같은 안내.
- **강점**: 변경이 가장 작다(현재 데이터·폴링 그대로, Dashboard 재배치 위주), 좌석·방 크기를 크게 쓸 수 있다. **약점**: "사무실에서 모두 파악"의 "모두"가 선택 세션 안에 한정된다. 다른 세션 상황은 목록·띠에 의존.

### (다) 혼합 — 세션 스트립 + 선택한 방 확대

사무실 영역 위쪽에 **세션 스트립**(세션마다 작은 방 타일 1개: 이름 + 세션 상태 배지 + BOT 요약 한 줄), 아래에 선택한 세션의 **큰 방**을 둔다. 스트립 타일은 (가)의 방을 축소한 요약이고, 눌러서 큰 방으로 확대(= (나)의 선택). 승인 대기 세션은 스트립 맨 앞·굵은 테두리.

**1280**
```
| [!] 승인 대기 1개 세션                                              |
| 플랜 5h 42% | 7d 84% (!)  측정 3분 전                                |
| [demo !승인 대기|BOT3|Bash] [other …생각 중|BOT1] [+]  ← 세션 스트립  |
| +---------------- 사무실 (demo) [방 보기|목록 보기] ------------+  |
| | demo main opus-5-5 [!승인 대기 3분째]                         |  |
| | 승인 대기:(!)책임자  책상:(▶)QA ×3 (…)설계  쉬는 곳:(✓)기획    |  |
| +----------------------------------------------------------------+ |
```
**390**: 스트립을 2열 타일 격자로(세션 6개 이하) 맨 위에 두고, 선택 방은 그 아래. 세션이 7개 이상이면 승인 대기·최근 6개 + "더 보기(N)" 버튼. 방 보기/목록 보기 전환은 방 머리 위.

- **세션 상세 대체**: (나)와 같음 + 스트립 타일 툴팁에 세션 요약(모델, BOT 상태별 개수).
- **승인 대기 강조**: 스트립에서 모든 세션의 승인 대기가 보인다(방 테두리 3px + 배지). 선택 방 밖의 승인 대기도 사무실 영역 안에서 보인다 — (나)의 약점을 해결.
- **빈 상태**: (나)와 같은 자동 선택. 세션 1개뿐이면 스트립을 숨기고 방만 크게.
- **강점**: 전체 상황(스트립)과 상세(큰 방)를 한 영역 안에서, 공간 효율이 (가)보다 좋다. **약점**: 요소 종류가 가장 많아 구현·명세 부담이 크다(스트립 타일은 새 컴포넌트).

## 4. 접근성 (사무실이 메인이 되면)

공통 전제: 지금의 `aria-hidden`(플랜 미니)과 "아바타는 포커스 대상 아님" 근거는 "같은 정보가 BOT 목록·상세에 있다"였다. 목록·상세가 사라지므로 **사무실 쪽에서 같은 정보를 보조 기술에 제공해야 한다.** 세 선택지 공통 필수 사항:

1. **목록 뷰 전환(필수)**: 사무실 머리에 "방 보기 | 목록 보기" 토글(버튼 2개, `aria-pressed`). "목록 보기"는 같은 데이터를 표 대신 방(세션)별 정의 목록으로 보인다: 세션 → BOT 행(AgentRow: 이름·역할·StatusBadge·현재 도구·스킬 칩·모델·부른 BOT). 선택은 `localStorage`에 기억하고, 스크린 리더 사용자를 위해 **첫 포커스 가능 요소**로 둔다. 목록 보기는 현재 세션 상세의 정보와 동일하므로 기존 AgentRow·StatusBadge를 재사용한다.
2. **사무실 목록 마크업 유지**: 방 보기에서도 `<ul aria-label>`로 BOT을 "{이름}, {상태 문구}, 스킬 N개, 모델 …" 텍스트로 제공(12.6의 "시각적으로 숨긴 목록"을 방 단위로 확장). 시각 요소는 `aria-hidden`, 목록이 SR 전용. 단 목록 보기가 켜져 있으면 중복되므로 한쪽만 읽히게(`hidden` 전환).
3. **플랜 계기판**: 사무실이 `aria-hidden`이 아니게 되므로 상단 띠(PlanUsagePanel)가 사라지면 계기판이 `role="meter"` + `aria-valuetext`를 이어받아야 한다(PlanUsageMeter 규칙 그대로). 상단 띠를 남기면 계기판은 `aria-hidden` 유지(중복 방지). 사무실이 메인이므로 "상단 띠 제거 + 사무실 안 meter" 쪽을 권한다(Q-8).
4. **포커스 가능화**: 방 보기에서 BOT 아바타 = `<button>`(툴팁 카드 열기, `aria-expanded`, 카드는 `role="dialog"`가 아닌 인라인 비모달 `aria-describedby` 연결). Tab 순서: 승인 대기 BOT → 책상 BOT → 쉬는 곳 BOT(좌→우), 방 단위로 묶음. 아바타가 12개를 넘을 수 있으므로 **구역·방 단위 건너뛰기 링크**("승인 대기로 이동")를 둔다. 모든 버튼 44×44 이상(모바일), 포커스 링 2px ink.
5. **승인 대기 알림**: WaitingBanner `role="status"` 유지. 사무실 안 말풍선에는 `aria-live`를 두지 않는다(3초 폴링 반복 읽기 방지).

선택지별 추가:

| 선택지 | 추가 접근성 |
|---|---|
| (가) | 방이 `<section aria-labelledby>`(방 머리 = h3)라 제목 이동으로 세션을 건너뛸 수 있다. 접힌 방은 `<button aria-expanded>`. 방이 많을수록 Tab이 늘어 건너뛰기 링크 중요 |
| (나) | 세션 목록이 현재와 같은 `<ul>`/`aria-current`라 가장 익숙. 사무실은 선택 방 하나라 Tab 수가 가장 적다 |
| (다) | 스트립 타일 = 세션 선택 버튼(`aria-current`), 큰 방 = (나)와 같다. 스트립·방 두 곳의 포커스 이동 순서를 명세에서 정해야 한다 |
